## 7. 绝对不要再踩的坑

### 7.1 CSS 文件存在大量“后写覆盖前写”的历史规则

`app/globals.css` 是累积迭代的长文件，含多个同选择器、多个 `@media (min-width:801px)` 和 `!important`。此前出现过“代码看似改了、页面却没变”，真实原因是较晚的规则重新覆盖了早期规则。

**规则：**

- 修改前先用 `rg -n '选择器' app/globals.css` 查同类规则。
- 对紧急修复，追加到文件最末端作为最终覆盖；完成后应整理合并，避免继续堆叠。
- 不要只依据源码片段判断，要读取浏览器 `getComputedStyle` 验证最终值。

### 7.2 头像被裁切的根本原因

用户提供的橙色涂鸦头像是**正方形 1254×1254**。当它放进竖向容器且使用：

```css
object-fit: cover;
```

会裁掉涂鸦的一部分。用户要求“完整、一模一样复刻”。最终规则应保持：

```css
object-fit: contain !important;
object-position: center center !important;
```

并使用正方形容器。不要再改回竖向裁切框。

### 7.3 “一屏展示”与内容裁切之间的冲突

关于我桌面端当前使用固定视口高度和 `overflow:hidden` 达成一屏展示。任意增加字体、间距、图片高度，都可能让内容被裁掉。

**每次改动关于我布局后，都必须用至少 1200×615 的浏览器截图检查页面底部。**

### 7.4 不要把“构建成功”等同于“用户可预览”

此前用户反馈“页面无法预览”。必须同时确认：

1. 开发服务器仍在运行；
2. 实际端口；
3. `curl -I http://localhost:<port>/` 返回 200；
4. 在浏览器实际打开并截图；
5. 最终回复中给出可点击链接。

### 7.5 不要忽略用户的精确视觉批注

用户常提出精确像素、色彩、间距和层级要求（如 15px、20px、时间标签、关键词位置、手绘色条覆盖范围）。要遵循批注，且需要在页面上实际复核，而不是仅写出看似相近的 CSS。

### 7.6 用户要求的“可编辑框”后续已改变

项目详情最初要求三个可编辑框，后续用户明确要求“灰色的框不用调节，不可动”。当前实现已是固定展示卡片，而不是 textarea。不要在未确认时改回可编辑文本框。

### 7.7 不要误把浏览器批注截图中的蓝色标记当成页面样式

蓝色框、编号气泡是 Codex 浏览器批注层，不是网站设计本身。判断页面视觉时要区分它们。
